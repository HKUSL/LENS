**Threat Model:**

- **Attack Assumption:**  
  A publicly reachable MME exposes S6a and accepts unauthenticated Diameter peers. The attacker can impersonate the normal sender role for `Insert-Subscriber-Data-Request`, i.e. an HSS/CSS, and send a forged IDR to the MME for a known subscriber IMSI.

- **Attacker Capability:**  
  The attacker can establish its own Diameter connection to the victim MME, send crafted IDRs, and receive the corresponding answers. The attacker cannot observe or alter legitimate HSS<->MME traffic and is not a real serving or user-plane network element. The analysis is therefore limited to what the MME itself will store and later do with the specific field value.

**Exploitability Analysis:**

`Subscription-Data.APN-Configuration-Profile.APN-Configuration.MIP6-Agent-Info.MIP-Home-Agent-Address` is field-specific exploitable under this threat model.

Normally, IDR on S6a is sent from HSS to MME. The target field is inside `Subscription-Data`, under a specific `APN-Configuration`, and is therefore processed by the MME as authoritative subscriber provisioning data, not as transient metadata. Per the supplied evidence from TS 29.272, the MME replaces or adds the received subscription sub-tree, and APN configurations are stored per subscriber and per APN context. If `All-APN-Configurations-Included-Indicator` indicates full inclusion, the MME deletes all prior APN configurations and stores the received set; otherwise replacement occurs by `Context-Identifier`.

The target AVP itself has concrete routing semantics. In TS 29.272 it is defined as an `Address` containing the IPv4 or IPv6 address of the PDN-GW, and that address "shall be used as the PDN-GW IP address." The same evidence states that if `MIP6-Agent-Info` is present and `PDN-GW-Allocation-Type` is absent, the MME interprets the PDN-GW address as statically allocated. TS 23.401 then gives the downstream consequence: when HSS provides the identity of a statically allocated PDN-GW, no further PDN-GW selection is performed.

That creates a direct, field-attributable attack chain:

1. The attacker forges an IDR containing a modified APN entry for the subscriber.
2. The MME stores that APN configuration.
3. The modified `MIP-Home-Agent-Address` becomes the PDN-GW address bound to that APN entry.
4. On later attach or UE-requested PDN connectivity using that APN, the MME uses the stored APN configuration during PDN-GW selection.
5. Because the field explicitly supplies the PDN-GW IP address, the MME can target the attacker-chosen or invalid PDN-GW address in downstream session establishment.

This is a distinct field-specific security effect, not merely generic "forged IDR causes trouble." The additional capability introduced by this field is precise control over the PDN-GW address used for one APN subscription context. That can produce:
- wrong PDN-GW selection or misrouting for the subscriber's APN;
- PDN connectivity failure if the address is unreachable or nonfunctional;
- persistent service outage for that APN until subscriber data is refreshed;
- broader impact if the targeted APN entry is also the profile's default APN context.

The impact is strongest if the attacker modifies the APN configuration whose `Context-Identifier` matches the profile-level default `Context-Identifier`, because TS 23.401 indicates the default APN is used during attach when the UE does not specify an APN. In that case, ordinary attach can consume the malicious state without any special UE behavior.

Recovery is not immediate. The MME stores the bad value as subscriber state and will keep using it until a later legitimate provisioning event overwrites it, such as a subsequent IDR, ULA-driven refresh, or subscriber-data deletion/update. Attach itself does not repair the state; it may instead trigger the harm.

Because the field is authoritative, stored, and later consumed in concrete PDN-GW routing/selection logic, it meets the threshold for independent exploitability.

**Attack Procedure:**

Craft a forged `Insert-Subscriber-Data-Request (Command-Code 319, Application-Id 16777251)` from the attacker-controlled fake HSS to the victim MME. Include only the mandatory top-level AVPs and the minimal grouped subscription structure needed to define a coherent APN configuration carrying the target field.

To maximize observable impact, target the subscriber's default APN context by making the profile-level `Context-Identifier` equal the `APN-Configuration`'s `Context-Identifier`. Include:
- `User-Name` with the target IMSI,
- `Subscription-Data`,
- `APN-Configuration-Profile`,
- one `APN-Configuration`,
- `MIP6-Agent-Info`,
- the target `MIP-Home-Agent-Address`.

Use a malicious but syntactically valid test value for `MIP-Home-Agent-Address`, such as an unreachable IPv4 address (`203.0.113.66`). Omit `PDN-GW-Allocation-Type` so the MME interprets the supplied PDN-GW address as statically allocated, consistent with the provided evidence.

Expected success condition: the MME accepts the IDR and stores the APN configuration. On the subscriber's next attach or PDN connectivity attempt for that APN, session establishment is attempted using the malicious PDN-GW address, causing wrong routing or connectivity failure.
