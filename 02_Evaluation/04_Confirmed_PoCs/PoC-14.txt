### **Threat Model:**
- **Attack Assumption:**
  - The victim is the **MME** on **S6a**, and the attacker impersonates the **HSS** to send a forged `Insert-Subscriber-Data-Request (IDR)` directly to that MME. The MME accepts the request as authoritative subscriber-provisioning input and updates the targeted UE's cached subscription profile, including APN configuration data.
- **Attacker Capability:**
  - The attacker can open its own Diameter connection to the exposed MME, send crafted **IDR Requests**, and receive the corresponding Answers. The attacker knows the target subscriber identity (for example the IMSI in `User-Name`), but does **not** control legitimate HSS links, radio procedures, GTP/NAS signaling, or downstream PGW infrastructure beyond what the forged subscriber data itself can influence.

### **Exploitability Analysis:**
- `Subscription-Data.APN-Configuration-Profile.APN-Configuration.APN-OI-Replacement` is not mere metadata; it is an **authoritative 3GPP subscriber-profile leaf** inside the HSS-provided APN configuration that the MME stores for the UE. It is optional, vendor-specific (`Vendor-Id 10415`), string-like (`OctetString`) data, but when present it directly affects how the MME later derives or validates the **operator identifier portion** of a full APN for that specific `APN-Configuration` instance.
- The field-specific causal chain is concrete: a forged IDR carrying a modified `APN-OI-Replacement` for a chosen `Context-Identifier` causes the MME to overwrite the cached APN configuration entry for that subscriber; on a later attach/PDN-connectivity event, the MME uses that stored value during APN construction/selection; the resulting full APN can differ from the legitimate one; that changed APN is then used in downstream EPC session establishment toward SGW/PGW selection and APN routing.
- Because the changed behavior depends on the **value of this field itself**, the incremental impact is field-specific. A malicious but syntactically valid replacement can cause **wrong APN selection**, **unknown/unroutable APN use**, **default PDN establishment failure**, or routing into a different accepted APN namespace if such an alternate OI is valid in the operator environment. This is a real subscriber-state poisoning path even without any extra attacker control over radio or GTP links.
- The impact is usually **deferred rather than immediate**: receiving the IDR does not by itself tear down bearers, but it corrupts cached provisioning that the MME later consumes during session establishment. That still satisfies field-specific exploitability because the later failure or misrouting occurs specifically because `APN-OI-Replacement` changed.
- Limits remain important: if the attacker chooses an invalid OI, the likely result is denial of service for future PDN setup rather than useful redirection; if the chosen alternate OI is not actually provisioned downstream, session setup may simply fail. Even so, the field still supports a concrete field-driven attack path: persistent corruption of APN construction logic for the targeted subscriber until later legitimate HSS resynchronization, detach/context deletion, or a fresh profile download overwrites it.

### **Attack Procedure:**
- Craft a forged S6a `Insert-Subscriber-Data-Request` from the spoofed HSS identity to the target MME, including the target subscriber `User-Name`, standard request AVPs, and a `Subscription-Data` subtree containing `APN-Configuration-Profile`.
- Inside one `APN-Configuration`, include at minimum a coherent `Context-Identifier`, `Service-Selection`, and the malicious `APN-OI-Replacement`; include `All-APN-Configurations-Included-Indicator` at profile level so the update is interpreted coherently.
- Set `APN-OI-Replacement` to a syntactically valid but wrong operator identifier so the MME accepts and stores it for that APN entry.
- The expected success condition is that the MME returns a successful IDA, and on the subscriber's next attach or PDN connectivity procedure the resulting APN is altered, causing session failure or different APN routing behavior.
